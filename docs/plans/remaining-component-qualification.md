## 2. Component Qualification Strategy

### 2.1 Single-Stage Composition & Memory Isolation
- To avoid loading the default embedding model alongside the reranker or generator, the server and model manager must support explicit single-stage execution (`model_name=None` or `--no-embed`).
- Each qualification smoke runs sequentially in isolation:
  1. Offline unit and fixture tests execute first.
  2. Reranker 4B smoke executes with $\ge 6000\text{MB}$ verified headroom on ports 8797/8798; supervisor reaps and verifies complete process exit.
  3. Generation 1.7B smoke executes with $\ge 3000\text{MB}$ verified headroom on ports 8797/8798; supervisor reaps and verifies complete process exit.
- Production port 8787 and live background services remain untouched throughout.

### 2.2 Public Judged Evaluation Fixtures
- Fixtures utilize public query/document pairs with known relevance judgments:
  - Technical / Programming: REST API versioning, Raft/Paxos consensus, database indexing.
  - Negative / Distractor pairs: Recipes, unrelated policies, arbitrary text.
- Validation checks:
  - Relative score ordering: $P(\text{relevant}) > P(\text{irrelevant})$.
  - Numerical sanity: finite floats in $[0.0, 1.0]$, no NaNs or Infs.
  - Cardinality and ordering: input pair order strictly preserved.
  - Determinism: repeated calls with temperature 0 yield identical results.
  - Input boundaries: empty/whitespace rejected with HTTP 400; over-budget tokens rejected with HTTP 400.
  - Resilience: cancellation mid-decode or timeout cleanly aborts without leaving orphaned GPU worker threads or leaked memory.

### 2.3 Strict Vector Space Isolation Principle
- **Vector Space Invariance**: Vectors generated by different models (e.g. 4B vs 0.6B) or different architectures reside in non-comparable semantic metric spaces.
- **Rule**: Never query a 4B indexed database with 0.6B query embeddings (or vice versa).
- **Index Management**: Any transition between embedding models requires a separate, isolated index build (via shadow indexing) with zero cross-space querying.
- **Dimensionality vs Quality**: Higher vector dimensionality (e.g. 2560d vs 1024d) does not inherently guarantee higher recall without empirical evaluation and model-index compatibility.

# Parent source review: remediation inputs

These are source-backed initial findings against 0e0ce47, not a completion report. Audit and add deterministic regressions before accepting fixes.

IMPORTANT ADDENDUM: Read `docs/reviews/deep-audit-additional-findings.md` before tests or completion. Default Python fixtures currently load real models; replace with mocked offline fixtures or gate real-model tests explicitly before running a full suite. Independent review found adapter self-deadlock, wrong 4B model batching metadata, inconsistent weight estimates, and no-op timeout regression.

Additional parent-verified TypeScript contract defect: `src/embedding/contract.ts::computeEmbeddingSpaceId` omits `descriptor.tokenizer` despite the interface/contract promising tokenizer compatibility. It also lowercases model identifiers (can collapse case-sensitive local model paths). Trace migration semantics before fixing, add differing-tokenizer/case-sensitive-path tests, never silently migrate existing vectors. `scripts/bench_representative.py` records batch_size but does not apply it to the per-stratum tokenized input; uses hardcoded planner 8192 and no production client/index path. Its docstring claims serialization/disk breakdown not present. Make benchmark labels/metadata truthful and CLI parameters effective; do not claim GGUF comparison from this microbenchmark.

1. **HIGH: post-load accounting omits newly loaded stage.** `scripts/qmd_mlx/model_manager.py::_do_load_internal` calculates `_get_resident_model_mb()` before marking the new stage READY; that helper only counts READY stages. A model whose actual size exceeds its estimate can push total residency over budget without eviction, provided its individual size fits. Regress two adapters: already-resident + underestimated newly-loaded each fits alone, combined exceeds budget. Ensure eviction or rejection and correct accounting after failed/partial load.
2. **HIGH: owner-thread guarantee bypassed during shutdown.** `ModelResidencyManager.unload` catches executor submit exceptions and calls `_do_unload()` on the caller thread even if owner is still forwarding. `MLXEmbeddingRuntime.shutdown` also falls back to `adapter.unload()`. Regress blocked forward + unload timeout/cancellation and assert no off-owner or concurrent adapter unload; cleanup must wait for safe ownership, not race the GPU.
3. **HIGH: tokenization races eviction.** `MLXEmbeddingRuntime.submit_embed` and `tokenize` test/load the adapter, then tokenize outside owner thread with no lifecycle lease. Other-stage loads or idle eviction can clear tokenizer between those steps. Regress deterministic eviction between load and tokenize. Also ensure bounded request admission applies before load/tokenize and large CPU allocations, not merely each forward micro-batch.
4. **HIGH: default-model resumability fingerprint inconsistency.** `src/indexing/job.ts::runDurableIndexingJob` compares existing fingerprint.model to `options.model || 'default'`, but saves `descriptor.model || targetModel`. With an available real descriptor and omitted model option, resume falsely rejects the same model. Resolve one effective model identity and use it consistently. Add production-path resume test with omitted model and a real-shaped descriptor.

Scope: repository code/tests/docs only. No actual model inference, live DB writes, deployment, model downloads or pushes during remediation. Performance superiority remains unverified until safe matched-workload measurements; mocked regression tests cannot establish it.
